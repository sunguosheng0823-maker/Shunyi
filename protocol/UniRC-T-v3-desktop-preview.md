# UniRC-T v3 桌面预览扩展

状态：2026-09-15 首个 macOS 预览实现。认证、加密、证书轮换规则沿用 [v2](UniRC-T-v2.md)。本版本不实现账号业务，也不使用 RustDesk 的公共设备目录或中继服务。

## 版本协商与认证

1. 中继接受终端版本 `2` 与桌面版本 `3`。仅当设备在本地显式开启桌面共享、且找到引擎时，Agent 注册版本 `3`。
2. 新建桌面连接使用 `Hello.version=3`；中继在建立 TLS 设备通道之前拒绝版本 `2` 的目标，错误 `desktop_unavailable`。此失败不会使用一次性密码。
3. 设备 CA 摘要验证、内层 TLS、连接证书或临时密码认证全部完成后，才接受 `desktop_open`，再检查本地授权，最后启动采集引擎。
4. 长期证书轮换约束新建认证。临时密码在首次成功认证时被消耗，同一 TLS 会话可以创建终端和桌面；不能以该密码建立第二条 TLS 会话。有效凭据不会绕过本机桌面策略或系统权限。

## 本地权限

`denied` 为默认值；`view` 允许查看；`control` 允许查看和输入。只读会话的 `desktop_input` 会被 Agent 拒绝并关闭该桌面，既有终端继续运行。升级安装不会自动把桌面权限授予旧凭据。macOS 录屏与辅助功能权限另行由操作系统检查，凭据和 root 身份不能替代系统许可。

桌面启动失败或权限变更后，使用新的临时密码重试可能是必要的：密码已经用于成功的设备认证，并不会因为后续桌面启动失败而恢复可用。当前桌面模式不能在原会话内从查看升级为控制；关闭并按所需模式重新连接。

## 内层 Access 消息

所有消息均在内层 TLS 中传输。JSON 使用 `kind`，未知字段拒绝。二进制帧和终端消息共用 v2 的封包方式；下表字段不包含 `kind`。

| kind | 方向 | 字段 / 二进制体 |
| --- | --- | --- |
| `desktop_open` | 控制端 → 设备 | `desktop` UUID、`display` 屏幕索引、`control` 布尔值 |
| `desktop_opened` | 设备 → 控制端 | `desktop`、`display` 信息、实际 `control` |
| `desktop_frame` | 设备 → 控制端 | `desktop`、`sequence`、`offset`、`total`、`width`、`height`；二进制体是画面分片 |
| `desktop_input` | 控制端 → 设备 | `desktop`、`event` |
| `desktop_close` | 控制端 → 设备 | `desktop` |
| `desktop_closed` | 设备 → 控制端 | `desktop`、`reason` |

屏幕信息：`width`、`height`、`origin_x`、`origin_y`、`scale`、`cursor_embedded`。当前 UI 使用第一个屏幕，不提供屏幕切换器；协议保留索引以支持后续扩展。

输入按 `type` 区分：`pointer {x,y}` 的坐标为 `[0,1]`；`button {button,down}`；`scroll {x,y}`；`key {key,down}` 使用明确支持的浏览器 `KeyboardEvent.code`；`text {text}`；`release_all`。坐标、长度和滚动范围在接收端验证。按下、抬起保持顺序；失焦、离开画面或关闭时释放本会话持有的键和鼠标按钮。

## 媒体与限制

本阶段复用 RustDesk 的平台采集、VP8 编解码和输入模块。媒体体是固定上游版本的 `VideoFrame` Protobuf，因此不能称为“全部媒体格式已独立重写”。外层设备发现、授权、TLS、会话与分片属于 UniRC。

- 保留 64 KiB 外层封包上限；每片至多 16 KiB；单个压缩画面至多 8 MiB。
- 每个桌面只重组一帧；拒绝越界、缺片、交错和尺寸变化的分片。
- 像素数不超过 16,777,216，任一边不超过 8192。解码前检查 VP8 关键帧的真实尺寸，拒绝与外层声明不符的内容。
- 初版使用 VP8 软件编码，目标节拍 10 次/秒；静止画面不重复发送。实际帧率和时延尚未完成跨网基准测试。
- 控制端在本地独立引擎中解码，再经二进制 Tauri Channel 向 Canvas 送 RGBA。每帧要求 UI 确认，限制在途画面数量；不使用终端文本事件传视频。
- 设备同一时间只接受一个采集会话。关闭最后一个终端不会终止尚存的桌面；断开整个 TLS 通道会清理所有子会话。
- 引擎独立进程按会话启动，关闭 stdin 后给予最多 2 秒释放输入并退出；异常终止仍需在后续故障注入中继续验证系统按键状态。

当前传输为可靠中继通道，尚未继承 RustDesk 的打洞、弱网优化或独立媒体调度；没有音频、剪贴板同步、文件传输、多屏切换、无人登录桌面、UAC 安全桌面或 FileVault 登录前控制能力。

## 验证

自动化测试覆盖旧终端协议、认证、证书轮换、临时密码不可复用、大帧分片、只读输入拒绝、终端/桌面共存和版本拒绝不消耗密码。传输测试使用明确标注的合成引擎；真实平台采集与输入结果另见 `docs/verification/desktop-preview-2026-09-15/`，不将合成帧测试视为真实屏幕验收。
